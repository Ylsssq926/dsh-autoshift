# Model Autoshift (模型自动挡)

> Всё ещё выбираешь модели вручную? Переключись на Auto.

Накопил кучу релейных моделей и до сих пор выбираешь по одной под каждую задачу? Model Autoshift добавляет передачу **Auto** в селектор моделей DSH: бросаешь задачу — он выбирает лучшую модель из уже настроенных. Дешёвые модели на рутину, флагманы на сложное. Один маршрут закреплён на всю сессию, не сбивается после перезапуска, ноль дополнительных вызовов модели.

Ты даёшь задачу. Auto выбирает модель.

## Зачем Auto

- **Ноль настройки**: установил, выбрал Auto, поехал. Не надо наполнять пул или писать YAML. Все модели, настроенные в DSH — официальные или релейные — распознаются, даже незнакомые ID.
- **Переключается по задаче**: инженерия, творчество, письмо, исследование, архитектура и повседневное — шесть типов задач сопоставляются автоматически, дешёвые модели на рутину, флагманы на сложное.
- **Одна сессия — один маршрут**: первая выбранная модель закрепляется на всю сессию. Сжатие контекста и перезапуск десктопа восстанавливают маршрут, а не выбирают заново, сохраняя контекст и кэш провайдера стабильными.
- **Ноль дополнительных вызовов**: каждый запрос идёт ровно в одну модель — никакой «модели-роутера», сжигающей второй вызов, без голосования, без прогрева, без повторов по умолчанию. Usage проходит как есть; счёт не меняется.
- **Каждый ход виден сразу**: строка-квитанция в конце каждого ответа — `Auto · model · tier · role` — показывает, кто отработал, какой уровень и был ли резерв.

## Для кого

- **Продвинутые пользователи релея**: десятки или сотни моделей, без ручного переключения под каждую задачу;
- **Мультипровайдерные пользователи**: DeepSeek, OpenAI, Gemini, Claude вперемешку, распределение по задаче;
- **Новички**: пропусти изучение моделей, выбери Auto, начинай.

## Установка

```bash
dsh plugin --profile web add -w link:/path/to/model-aware-auto-plugin
```

Перезапусти DSH и включи плагин. Новые сессии покажут **Model Autoshift → Auto** в селекторе моделей. Для десктоп-приложения используй `--profile desktop`.

## Быстрый старт

1. Настрой хотя бы одну текстовую модель в настройках DSH (официальную или релейную);
2. Новая сессия, выбери **Auto**;
3. Дай задачу.

Вот и всё.

## Три режима

| Режим | Поведение |
|---|---|
| `economy` | Рутина идёт на дешёвые модели; вес стоимости максимален |
| `balanced` (по умолчанию) | Сначала соответствие задаче, стоимость учитывается |
| `quality` | Только соответствие задаче, стоимость игнорируется |

```yaml
mode: economy
```

## Примеры задач

| Роль | Что бросаешь |
|---|---|
| Инженерия | Починить стектрейс, отрефакторить функцию, написать скрипт, задеплоить API, прогнать тесты |
| Творчество | Написать стих, придумать историю, ролевая игра, набросать копирайт |
| Письмо | Отшлифовать письмо, суммировать статью, перевести, написать недельный отчёт |
| Исследование | Обзор литературы, сравнение вариантов, прогон бенчмарка |
| Архитектура | Дизайн системы, выбор технологий, разбиение на микросервисы |
| Повседневное | Болтовня, вопросы и ответы, всякая рутина |

Какую бы роль ни дала задача, Auto выбирает модель под эту роль из твоего пула — рутина в economy, сложное как флагман.

## Релейные модели распознаются без настройки

Релейные пулы полны незнакомых ID. Auto ранжирует их по имени и распределяет:

- **Economy**: `mini / flash / lite / haiku / free / turbo`, плюс небольшие открытые модели вроде `7b / 8b`;
- **Флагман**: `pro / opus / ultra / max`, плюс reasoning-модели вроде `r1 / o3 / reasoner / thinking`;
- **Инженерный уклон**: `coder / code / dev`, семейства deepseek/claude; **творческий уклон**: семейство gemini.

Дешёвый вариант флагманского семейства (`pro-flash`) всё равно считается economy. Пересылка всегда идёт по точному ID каталога. Для тонкой настройки стоимости или ролей переопредели через `economics` в `preferences` / `routes`.

## Закреплено на сессию, без сбоя при перезапуске

Первый успешный маршрут привязывается ко всей сессии. После сжатия контекста или перезапуска десктопа привязка восстанавливается из событий сессии, никогда не выбирается заново; контекст никогда не смешивается между моделями, а стабильный префикс дружелюбен к кэшу провайдера. Если закреплённую модель удалили, Auto подскажет следующий шаг, а не молча сменит модель посреди разговора.

## Квитанция маршрута

Небольшая строка в конце каждого хода: `Auto · model · tier · role`, плюс `fallback×N`, если был взят резерв. Она читает метаданные маршрута, уже присутствующие в сессии — ноль дополнительных запросов; ходы не-Auto ничего не показывают.

## Распределение субагентов (опционально)

Если нативный инструмент субагентов DSH включает выбор модели и у сессии есть дочерняя политика, Auto выполняет локальное сопоставление ролей плюс короткую передачу для подзадач **без явно указанной модели**. Явно выбранные модели субагентов всегда выигрывают; запуск, отмена, права и переработка остаются нативными в DSH.

## Права и данные

Auto читает только твои подключённые каталоги моделей и текущие события сессии и пересылает только провайдерам, которые ты настроил. Он не трогает файлы воркспейса и не отправляет телеметрию; вся конфигурация остаётся локальной.

## Конфигурация (всё опционально)

### Лёгкие предпочтения

```yaml
preferences:
  - provider: your-provider-id
    model: exact-model-id
    roles: [engineering]
```

Предпочтения лишь корректируют порядок; остальные подключённые модели продолжают участвовать.

### Контроль области

```yaml
scope:
  providers: [provider-a, provider-b]   # Allowlist, пусто = все
  excludeProviders: [provider-c]
  excludeModels: [some-model]
```

### Расширенные профили

Полный список `routes` переопределяет автообнаружение для фиксированных командных потоков или долгосрочной настройки: `roles`, `tools`, `behavior`, `dimensions`, `economics`, `contextWindow`, `maxOutputTokens`, `routeRevision`. Используй настоящие ID провайдера/модели DSH; никаких API-ключей в конфигурации.

## Полезно знать

- Только текстовые задачи; графические модальности вне каталога Auto;
- Старые сессии, начатые с другой моделью, нельзя переключить на Auto посреди разговора — начни новую сессию;
- Вспомогательные запросы (заголовки, сводки) следуют закреплённому маршруту сессии.
